# Meeting retention

Ja approved these rules on 2026-11-08:

- Browser recording audio stays recoverable until a nonempty transcript is durably saved to Supabase. After that save, Workbench removes its IndexedDB archive, pending audio blob and download URL. A failed cleanup leaves the audio available and shows a warning.
- Native capture directories under `WORKBENCH_CAPTURE_ROOT` are checked at gateway startup and daily. A directory with a valid gateway ledger older than seven days is removed unless its capture is active or its recorded helper process is still running. Failures go to the gateway error log. Unknown directories and directories without a valid creation timestamp are left alone.
- Migration `030_meeting_retention.sql` enables `pg_cron` and schedules a daily 03:17 database-time job. It clears `meeting_drafts.transcript` and `speaker_segments` one year after `transcript_saved_at`, recording the removal time in `transcript_expired_at`. Inserting nonempty transcript content, or saving a changed transcript or speaker segments, resets the one-year clock and clears a prior expiry marker. A notes-only save with unchanged transcript fields leaves the clock alone. Existing rows lack a historical edit timestamp, so the migration sets their retention anchor to migration time, giving them at least one more year rather than deleting them early. It preserves notes and meeting metadata. The cron job and its runs can be inspected in `cron.job` and `cron.job_run_details` after migration approval.

The migration is a draft and has not been applied. Verify the cron job, its first run and the M1 file cleanup after the approved deployment. Do not delete existing native recordings or run the SQL ahead of the M6 gate.

At the M6 database gate, verify the trigger with synthetic, rolled-back rows: a notes-only update that submits unchanged `transcript` and `speaker_segments` must leave `transcript_saved_at` unchanged; a changed transcript or segment array must advance it; saving new content after expiry must clear `transcript_expired_at`. Verify the scheduled job only clears rows whose latest transcript save is older than one year. A read-only check of the SQL change predicate covered those four cases, but the trigger and cron job have not run in this project.
